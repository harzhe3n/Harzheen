## Design decisions (remember these)
- Theme: near-black `#0d0d0d` with SILVER/GREY accent (user dislikes gold). Accent vars: `--accent` (#d4d4d4), `--accent-light` in style.css
- Fonts: **Syne** (headings/body) + **DM Mono** (`--font-mono`, all small labels/badges/pills) + **Space Grotesk** (`--font-display`, big section titles/detail titles) + **JetBrains Mono** (`--font-code`, hero code window). Owner swaps fonts by typing the name into the `--font-*` vars at top of style.css — script.js `initFontLoader()` auto-downloads any Google Font from those 5 vars (skips local/system fonts). The Google Fonts `<link>` in each HTML head only preloads the defaults; no longer needs editing when fonts change. All font-family rules use the vars — never hardcode font names in CSS
- Keep all existing animations when changing styles: drifting orbs, grid-lines backdrop, grain overlay, sheen on `.useful-btn`, staggered reveal animations, hover lifts, hero entrance (.hero-in/.hero-in-left with .d1–.d7)
- "Living silver" pointer effects (script.js initPointerEffects): cursor-follow aurora glow (kept SMALL at owner request — 340px), click ripple rings, card tilt + spotlight borders on .project/.useful-card/.link-card/.store-btn. Owner wants these to stay — they're the site's signature. Auto-disabled on touch devices and prefers-reduced-motion
- Language toggle (Aug 2026): fixed `.lang-btn` top-left on ALL pages — flag of the language you'd switch TO + code (KU/EN). English ⇄ Kurdish Sorani via I18N dict + data-i18n attrs in HTML; EXPERIENCE entries carry optional `ku` sub-objects; typed words come from I18N[lang].typedWords. Kurdish sets `<html dir="rtl" lang="ckb">` — CSS uses logical props (inset-inline-*, padding-inline-start) so layout mirrors; choice persists in localStorage key "hh-lang". PROJECTS/LINK_STORE content stays English (owner can add later)
- Hero particle network: vanilla canvas (`#particles`), initParticles() in script.js — mouse-reactive dots + link lines; pauses when tab hidden or hero off-screen; disabled under prefers-reduced-motion
- Status dot stays green ("Available for work" badge in hero)
- NO navbar by design (matches reference) — navigation is anchor scroll + the `.useful-banner` in the contact card (→ useful.html). The old fixed `.useful-pill` was REMOVED at owner request Aug 2026 ("extra"); `.lang-btn` keeps its exact position/alignment

## Project data schema (PROJECTS object in script.js)
- `type`: "linked" (has live link → shows Open Project button) or "case" (showcase only, no link button)
- `languages`: array of technologies shown as pills
- `link`: live URL (only used when type is "linked"); `code`: optional GitHub/repo URL (shows View Code button)
- `body`: array of paragraphs; `features`: optional array of bullet points ("add more detail")
- `previews`: optional array `{ image, desc }` — screenshots gallery on project.html, each with its own caption; section hides itself when absent/empty
- `tagline`, `image`, `title` — self-explanatory

## Link store schema (LINK_STORE object in script.js)
Keys = category slugs used as `links.html?cat=KEY`. Current keys: adobe, microsoft, blackops, torrent, steamtools, topaz
- Category: `name`, `tagline`, `logo` (image path or ""), `items` array
- Item: `{ name, url, desc, logo }` — logo is optional; missing/broken logos show a silver letter tile automatically
- Owner adds links by editing items himself — keep this workflow simple, never hardcode link cards in HTML
